# 인증과 온보딩

이 문서는 FE 로그인, 약관 링크, 온보딩 입력, 마케팅 정보 수신 동의 UI 기준을 정리합니다.

## 기준 문서

- 기능 요구사항: [요구사항 정의서](../requirements/requirements-definition.md)
- 기능 ID 연결: [기능 인덱스](../requirements/feature-index.md)
- API 사용 기준: [API 사용 기준](../api/frontend-api-usage.md)
- 라우팅 기준: [FE 라우팅 기준](../frontend/routing.md)

## 기능 범위

| 세부기능 ID | 기능 | FE 처리 기준 |
| --- | --- | --- |
| `AUTH-001`~`AUTH-004` | 로그인/회원가입 | 소셜 로그인 기반으로 인증을 시작하고 토큰을 저장합니다. |
| `ONBOARD-001`~`ONBOARD-010` | 온보딩 | 닉네임, 생년월일, 사용자 성별, 선호 스타일을 입력합니다. 선호 스타일은 공통 카탈로그의 style code 목록을 사용합니다. |
| `SYSTEM-008` | 이용약관 동의 | 온보딩 첫 단계에서 필수 체크박스로 제공하고 원문을 모달로 확인합니다. |
| `SYSTEM-009` | 개인정보 동의 | 온보딩 첫 단계에서 필수 체크박스로 제공하고 원문을 모달로 확인합니다. |
| `SYSTEM-010` | 마케팅 정보 수신 동의 | 온보딩 첫 단계에서 선택 체크박스로 제공하며 기본값은 미동의입니다. |

## 탈퇴 계정 복구 기준

- 회원 탈퇴 후 30일 이내 같은 계정으로 로그인을 시도하면 자동으로 로그인하지 않습니다.
- BE는 OAuth 성공 후 인증 쿠키를 바로 발급하지 않고 복구 확인 상태로 FE에 리다이렉트합니다.
- FE는 복구 확인 모달을 표시하고, 사용자가 복구를 선택한 경우에만 `POST /api/v1/auth/restore-withdrawn`을 호출합니다.
- 복구를 취소하면 비로그인 상태를 유지합니다.
- 탈퇴 후 30일이 지난 계정은 복구할 수 없으며 다시 로그인할 수 없습니다.

## 약관 표시 기준

- 로그인 모달 하단에 이용약관과 개인정보처리방침 확인 버튼을 제공합니다.
- 온보딩 첫 단계에서 이용약관과 개인정보처리방침을 필수 체크박스로 제공합니다.
- 필수 약관 2개를 모두 체크하지 않으면 다음 단계로 이동할 수 없습니다.
- 전체 동의는 필수 동의와 선택 동의를 함께 체크하는 편의 기능이며, 회원은 각 항목을 개별로 해제할 수 있어야 합니다.
- 체크박스 또는 약관 문구를 누르면 동의 상태만 변경하고, 약관 원문 모달은 별도 화살표 버튼으로 엽니다.
- 약관 원문은 BE `/api/v1/legal/{documentType}` 응답의 markdown `content`로 표시합니다.
- `documentType`은 `terms`, `privacy-policy`, `marketing-consent`를 사용합니다.

## 마케팅 정보 수신 동의 기준

- 마케팅 정보 수신 동의는 선택 동의입니다.
- 온보딩 첫 단계에서 체크박스로 표시합니다.
- 마케팅 정보 수신 동의 원문은 체크박스 영역에서 모달로 확인할 수 있게 합니다.
- 전체 동의로 선택되더라도 개별 체크박스로 해제할 수 있어야 합니다.
- 기본값은 미동의입니다.
- 동의하지 않아도 가입과 기본 서비스 이용은 가능해야 합니다.
- 마이페이지 또는 개인정보 수정 화면에서 동의/철회할 수 있어야 합니다.
- 마이페이지에서는 현재 동의 상태와 원문 확인 모달을 제공합니다.
- FE 화면에서는 동의 여부만 표시합니다. 동의/철회 일시는 BE 내부 관리 기준으로 둡니다.

## 선호 스타일 선택 기준

- 닉네임은 룩피드 프로필 식별에도 사용하므로 전체 회원 기준으로 중복될 수 없습니다.
- 닉네임은 영문 소문자, 숫자, 마침표(`.`), 밑줄(`_`)만 3~30자로 입력합니다.
- 닉네임의 처음과 끝은 영문 또는 숫자여야 하며, 마침표(`.`)를 연속으로 사용할 수 없습니다.
- 온보딩에서는 닉네임 입력 중 실시간으로 `GET /api/v1/users/nickname/check`를 호출해 규칙과 중복 여부를 안내합니다.
- 온보딩 스타일 선택지는 `GET /api/v1/categories` 응답의 style code/name/description을 기준으로 렌더링합니다.
- 카탈로그 API 조회에 실패하거나 style 목록이 비어 있으면 오류 상태를 표시하고 다음 단계 진행을 막습니다. 온보딩 화면은 FE 하드코딩 스타일 목록으로 대체하지 않습니다.
- 현재 style code는 `CASUAL`, `STREET`, `MINIMAL`, `SPORTY`, `CLASSIC`, `CHIC`, `WORKWEAR`, `CITYBOY`, `GORPCORE`, `RETRO`입니다.
- 온보딩에서는 사용자가 선호 스타일을 2개 이상 선택해야 다음 단계로 이동할 수 있습니다.
- FE는 선택한 값을 BE style code로 저장 요청합니다.
- 선택 배열의 첫 번째 값은 대표 스타일, 나머지 값은 보조 스타일 점수 계산 기준으로 사용됩니다.
- 온보딩 정보는 마지막 단계에서 한 번 저장하며, 프로필, 선호 스타일, 마케팅 정보 수신 동의가 일부만 저장된 상태를 남기지 않습니다.

## API 기준

| 기능 | Method | API 기준 | FE 처리 |
| --- | --- | --- | --- |
| 약관 원문 조회 | GET | `/api/v1/legal/{documentType}` | 로그인/온보딩/마이페이지 약관 원문 모달 표시 |
| 탈퇴 계정 복구 | POST | `/api/v1/auth/restore-withdrawn` | 복구 확인 모달에서 사용자가 복구를 선택한 경우 호출 |
| 닉네임 중복 확인 | GET | `/api/v1/users/nickname/check` | 온보딩/마이페이지 편집에서 닉네임 규칙과 중복 여부 실시간 확인 |
| 온보딩 완료 저장 | POST | `/api/v1/users/onboarding` | 프로필, 선호 스타일, 마케팅 정보 수신 동의 여부를 마지막 단계에서 한 번 저장 |
| 마케팅 동의 조회 | GET | `/api/v1/users/{userId}/marketing-consent` | 마이페이지에서 현재 동의 상태 표시 |
| 마케팅 동의 변경 | PATCH | `/api/v1/users/{userId}/marketing-consent` | 마이페이지에서 동의/철회 상태 반영 |

요청 예시:

```json
{
  "marketingAgreed": true
}
```

응답 예시:

```json
{
  "success": true,
  "data": {
    "marketingAgreed": true
  },
  "message": null
}
```

## 변경 기준

- 로그인, 온보딩, 마이페이지의 약관 노출 위치가 바뀌면 이 문서를 수정합니다.
- 마케팅 동의 API 경로, 요청 필드, 응답 필드가 바뀌면 [API 사용 기준](../api/frontend-api-usage.md)을 함께 수정합니다.
- 현재 코드와 공식 기준의 차이가 생기거나 해소되면 [FE 구현 정합성 현황](../frontend/implementation-gaps.md)을 함께 확인합니다.
