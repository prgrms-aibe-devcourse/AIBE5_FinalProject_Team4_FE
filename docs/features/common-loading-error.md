# 공통 로딩, 에러, 빈 상태 기준

이 문서는 FE 화면에서 API 호출 중 로딩, 실패, 빈 데이터를 처리하는 기준을 정리합니다.

## 기본 원칙

- API를 호출하는 화면은 loading, success, empty, error 상태를 구분합니다.
- 로딩 중에는 사용자가 같은 요청을 반복 실행하지 않도록 합니다.
- 실패 상태에서는 원인과 다음 행동을 제공합니다.
- 빈 상태는 오류가 아니며, 다음 행동을 안내합니다.

## 공통 상태

| 상태 | 의미 | 화면 기준 |
| --- | --- | --- |
| loading | 요청 진행 중 | spinner, skeleton, 진행 문구 |
| success | 요청 성공 및 데이터 존재 | 실제 데이터 표시 |
| empty | 요청 성공이나 표시할 데이터 없음 | 빈 상태 문구, 다음 행동 |
| error | 요청 실패 | 에러 메시지, 재시도, 공통 에러 페이지 |

## 상태별 필수 처리

| 상태 | 필수 기준 | 충족하지 않는 예 |
| --- | --- | --- |
| loading | 요청 중임을 사용자가 알 수 있어야 하며 중복 제출을 막습니다. | 저장 버튼을 계속 누를 수 있음 |
| success | API 응답의 `data`를 화면 상태에 반영합니다. | 응답을 받았지만 mock 목록만 계속 표시 |
| empty | 성공 응답에서 빈 배열 또는 null 결과를 오류처럼 표시하지 않습니다. | `[]` 응답을 500 오류 페이지로 이동 |
| error | HTTP status와 `message`를 기준으로 안내합니다. | 실패했지만 아무 안내 없이 기존 mock 유지 |
| network | 서버 연결 실패를 서버 내부 오류와 구분합니다. | 네트워크 끊김을 500 오류와 동일 처리 |

## 에러 페이지 기준

| 경로 | 사용 상황 |
| --- | --- |
| `/error/server` | 500 서버 내부 오류 |
| `/error/network` | 서버 연결 실패 또는 네트워크 오류 |
| `*` | 존재하지 않는 경로 |

화면별 부분 실패는 반드시 전체 페이지 이동으로 처리하지 않아도 됩니다. 추천 목록, 옷장 목록처럼 화면 일부만 실패한 경우 영역 단위 에러 메시지와 재시도 버튼을 사용할 수 있습니다.

404는 BE 기준 리소스 없음 오류입니다. 목록 API가 성공 응답으로 빈 배열을 반환한 경우에만 empty 상태로 처리합니다.

502는 BE 기준 외부 API 호출 실패입니다. 공통 API client에서는 5xx 범위로 `/error/server` 이동을 기본값으로 두며, 화면 단위에서 복구 가능한 외부 서비스 오류를 직접 처리하는 경우에만 별도 안내 메시지를 표시합니다.

## 기능별 기준

### 홈 추천

- 추천 목록 로딩 중 skeleton 또는 spinner를 표시합니다.
- 추천 결과가 없으면 옷 등록, 스타일 설정, 다른 라벨 선택 같은 다음 행동을 제공합니다.
- 추천 API 실패 시 실패 메시지와 재시도 행동을 제공합니다.
- 추천 API 실패 시 static fallback을 표시할 수 있지만, 실패 상태를 사용자에게 숨기지 않습니다.

### 옷장

- 옷장 통계와 목록을 각각 로딩할 수 있습니다.
- empty 상태는 사용자가 보고 있는 범위에 따라 판단합니다. 예를 들어 전체 옷장, 보유 탭, 미보유 탭, 선택한 필터 결과가 각각 empty가 될 수 있습니다.
- 옷장 empty 안내 문구는 탭과 무관하게 `옷이 없습니다.`를 기본으로 사용합니다.
- empty 상태에서는 옷 등록 진입 행동을 제공합니다.
- 옷장 목록 실패는 네트워크 오류 페이지 또는 영역 단위 에러로 처리합니다.

### 옷 등록

- 업로드 중, 분석 중, 초안 조회 중, 저장 중 상태를 구분합니다.
- 분석 실패 시 다시 업로드하거나 수동 입력으로 전환할 수 있어야 합니다.
- 저장 실패 시 입력값을 유지하고 재시도할 수 있어야 합니다.
- 분석 완료 전에는 최종 저장을 완료 상태처럼 표시하지 않습니다.

## 상태 처리 기준

- API 요청 중에는 사용자가 같은 요청을 중복 제출할 수 없도록 처리합니다.
- 서버 오류와 네트워크 오류를 구분합니다.
- 빈 목록은 오류처럼 표시하지 않습니다.
- 에러 발생 시 사용자가 취할 다음 행동을 제공합니다.
- 이미지 로딩 실패는 필요한 경우 이미지 영역 단위 상태로 처리합니다.
- AI 분석, 업로드처럼 시간이 걸리는 작업은 진행 상태를 표시합니다.
- 공통 상태 이름, 에러 라우트, 화면별 로딩/에러/빈 상태 처리 방식이 바뀌면 이 문서를 같은 PR에서 수정합니다.
